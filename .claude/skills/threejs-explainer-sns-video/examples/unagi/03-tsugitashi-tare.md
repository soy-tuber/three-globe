# 03 継ぎ足しのタレの中で何が起きているか

- 用途：店舗開発（店の独自性の説明、ブランドづくり）と、接客・厨房スタッフの教育
- 見る人：お客さん、ホールと厨房のスタッフ、出店先の関係者
- 状態：サンプル。「もっと知る」は2026年9月29日に各リンク先の本文で文言と数値を確認し、原文に合わせて直した（FACT-CHECK.md）

---

鰻店の継ぎ足しのタレの壺の中で、何が起き、どう味が保たれているのかを見せる、インタラクティブな3D解説ページを HTML 1枚で作ってください。
目的は、日本の SNS に30秒の画面録画を投稿して、多くの人に見てもらうことです。

# 見せたいこと
「創業以来の秘伝のタレ」は、創業時のタレがそのまま残っているわけではない。使った分だけ新しいタレを足すたびに、創業時のタレの割合は指数関数的に減っていく。
それでも味が続くのは、足すタレと、焼くたびに加わるもの（模型では鰻の脂と旨味が溶け込むと仮定する）が釣り合って、濃さが一定の値に落ち着くからだ。
これを、色の違う光の粒と「継ぎ足す量を変える」という操作1つで体感させる。
最初の2秒で「タレの壺」「漬けられる蒲焼き」「壺の中で混ざる光の粒」が一目で分かる絵にすること。

# 技術の条件
- index.html 1枚。three.js は importmap で https://cdn.jsdelivr.net/npm/three@0.183.2/ から読む
- 外部の3Dモデルと画像は使わない。形はすべてコードで作り、模様は CanvasTexture で描く
- フォントは Google Fonts のみ。それ以外の外部通信はしない
- 60fps で動き、コンソールエラーは0件。ピクセル比は低めから始め、余裕があれば上げる

# 守ること
- 他人の作品のコードや見た目を参照・模倣しない
- 実在の店名、屋号、ロゴ、特定の店のタレの配合や壺の意匠は使わない
- 呼び名は「タレ」「タレの壺」「継ぎ足し」にする
- 画面の文言はすべて日本語。「！」と絵文字は使わない
- 「濃さ」と「濃度」を混ぜない（画面では「濃さ」に統一する）。「旨味」と「うま味」を混ぜない
- 配合と温度管理、タレの成分の層と①〜⑥は「一般的な例をもとにしたイメージ」と明記する
- 鰻から溶け出す脂と旨味は、公的・学術資料で確認できていないので「模型の仮定」と明記し、事実として言い切らない

# 体験の流れ
① 初期状態：陶器のタレの壺の断面が見え、中で3色の粒がゆっくり対流している。創業時のタレの粒は深い琥珀、新しく足したタレの粒は明るい琥珀、鰻から溶け出した脂と旨味の粒は白い
② 操作：1日に継ぎ足す量（使った分の何割を入れ替えるか）を、壺の横の柄杓のドラッグで変える。ホイール、スライダー、↑↓キーでも同じ値が動く。柄杓に触れたときだけ量を操作し、それ以外のドラッグはカメラを回す
③ 変化：日付のカウンタが進むにつれて、創業時の粒が少しずつ減り、白い脂と旨味の粒が増えていく。濃さのメーターが揺れながら一定の値に近づく
④ しきい値を越えた瞬間：濃さが安定の帯に入り、壺の縁が白く光る。そのあと1本の蒲焼きがタレに漬けられて焼かれ、また戻るまでを約10倍のスローで見せる
   ①漬ける 焼いた鰻をタレにくぐらせる　②焼く タレが焦げて香りが出る　③溶け出す 脂と旨味がタレに移る　④減る 使った分だけタレが減る　⑤足す 新しいタレを足す　⑥混ざる 壺の中で釣り合う
⑤ 成功：短い「コトン」という音。表示に「創業時のタレの割合 ○%（模型の値）　濃さは安定」を出す（○は模型の計算値。依頼時の例は 0.3%）
⑥ 失敗・中断：継ぎ足しを止めるボタンを押すと、水分が飛んで濃さが上がりすぎ、メーターが赤に振り切れる。表示が赤で「煮詰まりすぎ」。カメラが少し引いて壺の縁の焦げを見せ、数秒後に継ぎ足しを戻すと元に戻る
⑦ 「分解」ボタン：タレの成分の層が浮き上がる（醤油／みりん／砂糖／鰻の脂と旨味／香ばしい焦げの成分）。粒は3倍に拡大し、そう明記する

# 物理（原理は正しく、数値は模型の値）
- ここでの「物理」は物質収支（入った量と出た量の釣り合い）とする
- 1日に割合 f を入れ替えるとき、n 日後に残る創業時のタレの割合は (1 − f)^n。このグラフを片対数で見せる
- 濃さ S は、1日ごとに次のように更新する：S(n+1) = (1 − f)·S(n)·（蒸発による濃縮）＋ f·S_new ＋（鰻から溶け出す分）。定常値 S* に収束することを見せる
- 濃さが安定の帯（S* ±5%）に入った時点をしきい値とする。継ぎ足しの割合の目盛りの中ほどで、約30日で帯に入るように模型の値を合わせる
- 粒の対流は、壺の中の簡単な渦の流れ場を RK4 で追う。粒の色の割合は、上の式の値と一致させる
- 煮詰まりすぎ：蒸発を大きくし、継ぎ足しを止めた場合の S の発散を上限で頭打ちにする
- NaN を出さない：長さ0のベクトルの正規化、0の0乗、負の数の pow を避ける

# 見た目
- 舞台：閉店後の鰻店の厨房。暗い室内、焼き台の残り火、白熱灯の温かい光、壺の釉薬に映る灯り
- 材質：深い茶色の釉薬の陶器の壺、檜の台、竹の柄杓
- 色の約束：
  - 創業時のタレは深い琥珀
  - 新しく足したタレは明るい琥珀
  - 鰻の脂と旨味は白
  - 安定の成立は白い閃光
  - エラーは赤
- UI は白〜グレーの細線にし、金色の装飾は使わない
- ブルームは解像度を落として控えめに使う

# 画面
- 見出し「継ぎ足しのタレの中で何が起きているか」を、最初の3秒だけ上中央に大きく出し、その後は小さく畳む
- リード：老舗の鰻店には、創業から継ぎ足してきたタレがあります。継ぎ足しを重ねるほど、創業時のタレの割合は小さくなっていきます。それでも味が続く理由を、継ぎ足す量を変えて見てください。
- メーター：タレの濃さ。線形。安定の帯に「味が落ち着く範囲」と付ける
- 小さなグラフ：日数と、創業時のタレの割合の曲線（片対数）。現在値の点と、1%の横線を入れる。注記「継ぎ足すたびに、昔のタレは同じ割合ずつ入れ替わっていきます」を添える
- 処理タイムライン：スロー中は「経過 12秒」のような実時間カウンタを出し、1本分の完了時に「この模型では、漬けて焼くまでの1回は十数秒です」と出す（秒数は模型の値）
- 小さなオシロスコープ：日ごとの濃さの揺れと、定常値の線
- 操作ボタン：1年を再生（自動で日付を進める）、分解、スロー／実時間、カメラ（全体／壺の中／焼き台／蒲焼き）
- 部品ラベルは引き出し線つき。重なったら優先度の低いほうを隠し、UI や表示パネルの上には置かない
- 成功と失敗は、壺のそばに大きな吹き出しでも出す
- 注記：割合と濃さは原理を示すための模型の値です。配合と温度管理、タレの成分の層と①〜⑥は、一般的な例をもとにしたイメージです。鰻から溶け出す脂と旨味は、模型の仮定です。タレの対流は目で見える速さに落とした模式表示です。
- Canvas に描く文字は、document.fonts.load で書体を読み込んでから描く
- スマホ幅（390px）：上に見出しとボタン、下のシートに継ぎ足す量・濃さ・①〜⑥・操作をまとめ、グラフとオシロは「開く」で出す

# もっと知る（出典リンクつきの開閉パネル。事実はこの2つだけを使う）
※ 2026年9月29日に、各リンク先の本文で文言と数値を確認した（FACT-CHECK.md）。

① 醤油、砂糖、みりんを用いたタレを使うようになって、鰻のかば焼きは大流行し、江戸っ子たちに愛される料理になったとされます。同じページの家庭向けレシピでは、タレを料理酒、醤油、砂糖で作ります。（農林水産省「うちの郷土料理」「鰻のかば焼き 東京都」 https://www.maff.go.jp/j/keikaku/syokubunka/k_ryouri/search_menu/menu/34_24_tokyo.html ）タレの作り方はいろいろありますが、味淋（みりん）1.8 l、醤油1.8 l、砂糖約113gの割合で作るのが基本といわれている、という解説もあります。（調理科学 12巻2号（1979）「ウナギ」 https://www.jstage.jst.go.jp/article/cookeryscience1968/12/2/12_85/_article/-char/ja/ ）
② 全体の量 V から、1回に S ずつ入れ替えることを n 回くり返すと、元のものが残る割合 R は R = ((V − S)/V)^n になります。1回に入れ替える割合を f（= S/V）とすると (1 − f)^n です。この式は、交換輸血の研究で、元の血液が残る割合を求める式として報告されています。（昭和医学会雑誌 30巻10号（1970）「新生児高ビリルビン血症患児の交換輸血によるビリルビン除去率の検討」 https://www.jstage.jst.go.jp/article/jsma1939/30/10/30_10_610/_article/-char/ja/ ）

# 検証用フックと録画モード
- window.__lab = { ready, setRefill(割合0〜1), getState(), tap(), setExploded(on), setCamera(name, instant), setSpeed('slow'|'real'), setDay(n) }
  - setRefill の直後の getState は、創業時の割合・濃さ・成功・失敗の判定まで反映済みの値を同期で返す
- ?demo=1 で30秒の自動再生にする。__lab.renderDemoFrame(t) で、時刻 t の状態を1フレーム同期で描けるようにする（動画の書き出し用）
- 台本と字幕（画面下中央に大きく、背景の帯つき）：
  - 0〜3秒　壺と蒲焼きの全体の絵「老舗の鰻店には、創業から継ぎ足してきたタレがあります」
  - 3〜7秒　壺の断面へ寄る「タレは使うたびに減り、そのぶん新しいタレを足します」
  - 7〜12秒　日付が進み、創業時の粒が減る「足すたびに、創業時のタレは同じ割合ずつ入れ替わります」
  - 12〜14秒　濃さが安定の帯に入る「それでも濃さは、ある値に落ち着いていきます」
  - 14〜18.5秒　スローで漬けて焼く「この模型では、くぐらせるたびに鰻の脂と旨味も加わるとしています」
  - 18.5〜23秒　安定の表示「この模型では、1年後に創業時のタレはほとんど残りません。残っているのは味の釣り合いです」
  - 23〜27秒　継ぎ足しを止める→煮詰まる「継ぎ足しを止めると、この模型ではタレが煮詰まっていきます」
  - 27〜30秒　分解した引きの絵「秘伝のタレとは、毎日の手入れが続いていることの証です」
