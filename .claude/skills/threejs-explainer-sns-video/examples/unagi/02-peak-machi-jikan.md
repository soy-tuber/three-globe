# 02 なぜピーク時に提供が遅れるのか（焼き台の数と待ち時間）

- 用途：店舗開発。席数と厨房規模の決定、出店計画の説明に使う
- 見る人：出店担当、オーナー、店長、厨房責任者
- 状態：サンプル。「もっと知る」の事実は出典を確認してから確定する（要確認）

---

鰻店で、注文が焼き台に並び、お客さんの待ち時間が生まれる仕組みを見せる、インタラクティブな3D解説ページを HTML 1枚で作ってください。
目的は、日本の SNS に30秒の画面録画を投稿して、飲食店の出店や運営に関わる人に見てもらうことです。

# 見せたいこと
焼き台が「ほぼ埋まっている」状態は、効率がよさそうに見えて実は危ない。稼働率が8割を越えたあたりから、待ち時間はゆるやかに増えるのではなく、崖のように跳ね上がる。
これを、光る注文の粒と「席数を増やす」という操作1つで体感させる。
最初の2秒で「客席」「焼き台」「流れてくる光る注文の粒」が一目で分かる絵にすること。

# 技術の条件
- index.html 1枚。three.js は importmap で https://cdn.jsdelivr.net/npm/three@0.183.2/ から読む
- 外部の3Dモデルと画像は使わない。形はすべてコードで作り、模様は CanvasTexture で描く
- フォントは Google Fonts のみ。それ以外の外部通信はしない
- 60fps で動き、コンソールエラーは0件。ピクセル比は低めから始め、余裕があれば上げる

# 守ること
- 他人の作品のコードや見た目を参照・模倣しない
- 実在の店名、ロゴ、チェーン店の店舗レイアウトや配色は使わない
- 呼び名は「焼き台」「客席」「注文」にする
- 画面の文言はすべて日本語。「！」と絵文字は使わない
- 「待ち時間」と「待機時間」を混ぜない。「稼働率」と「使用率」を混ぜない
- 厨房の配置は「一般的な例をもとにしたイメージ」と明記する

# 体験の流れ
① 初期状態：上から見下ろした店の模型。入口からお客さんの光の粒が入り、席に着くと注文の粒が厨房の焼き台へ流れる。焼き台の上では粒がゆっくり光りながら「焼き」の時間を過ごし、焼き上がると席へ戻る
② 操作：席数を、客席の端をドラッグして増減する。ホイール、スライダー、↑↓キーでも同じ値が動く。客席の端に触れたときだけ席数を操作し、それ以外のドラッグはカメラを回す
③ 変化：席を増やすほど注文の粒が増え、焼き台の稼働率メーターが伸びる。焼き台の前に待ちの粒の列ができ始める
④ しきい値を越えた瞬間：稼働率が約85%を越えると待ちの列が急に伸び、列が赤みを帯びる。そのあとピークの1時間を約60倍の早回しで見せる
   ①来店 お客さんが席に着く　②注文 注文が厨房に届く　③待ち 焼き台の空きを待つ　④焼き 焼き台で焼く　⑤盛り付け 重箱に盛る　⑥提供 お客さんのもとへ届く
⑤ 成功：席数が適正なときは、短い「チン」という音。表示に「平均の待ち時間 6分」を出す
⑥ 失敗・中断：席を増やしすぎると待ちの列が崩れるように伸び、表示が赤で「平均の待ち時間 40分」。カメラが少し引いて入口の外の行列を見せ、数秒後に席数が適正に戻ると列がほどける
⑦ 「分解」ボタン：店の模型が層に分かれて浮き上がる（客席／配膳の動線／盛り付け台／焼き台／仕込みと蒸し場）。焼き台の1台分は3倍に拡大し、そう明記する

# 物理（原理は正しく、数値は模型の値）
- ここでの「物理」は待ち行列の数理モデルとする
- 焼き台を c 台の窓口とする M/M/c 型の待ち行列で扱う。1時間あたりの注文数 λ、1台が1時間に焼ける数 μ、稼働率 ρ = λ / (cμ)
- 平均の待ち時間はアーラン C 式で求める：Wq = C(c, λ/μ) / (cμ − λ)。ρ が1に近づくと発散することが、グラフの形で分かるようにする
- 画面の粒の動きは、乱数の種を固定した離散事象シミュレーションで作る。こうすると renderDemoFrame(t) が決定的になる
- 表示する平均値は式の値を使い、粒の動きはそれを目で見せる補助にする
- 席数と注文数の関係は、席の回転を一定とした模型の値にする。焼き台の数は操作パネルで2〜6台を選べるようにする
- ρ ≥ 1 のときは待ち時間を上限（例：90分）で頭打ちにし、「列が伸び続ける状態」と表示する
- NaN を出さない：ρ ≥ 1 での割り算やゼロ除算を避ける

# 見た目
- 舞台：昼のピーク前の鰻店を、ミニチュアの模型のように上から見下ろす。木のテーブル、畳の小上がり、厨房のステンレス、白い暖簾（屋号なし）
- 材質：木目の机、白い漆喰の壁、ステンレスの厨房
- 色の約束：
  - お客さんと注文の粒は青白
  - 焼いている最中の注文は琥珀
  - 焼き上がりは白い閃光
  - 待ちが限界を越えたらエラーの赤
- UI は白〜グレーの細線にし、金色の装飾は使わない
- ブルームは解像度を落として控えめに使う

# 画面
- 見出し「なぜピーク時に提供が遅れるのか」を、最初の3秒だけ上中央に大きく出し、その後は小さく畳む
- リード：焼き台がいつも埋まっている店は、繁盛しているように見えます。でも余裕がなくなると、待ち時間は少しずつではなく一気に伸びます。席を増やして、その境目を見てください。
- メーター：焼き台の稼働率。線形。しきい値の破線に「待ちが急に伸び始めるライン」と付ける
- 小さなグラフ：稼働率と平均の待ち時間の曲線。現在値の点と、稼働率85%の縦線を入れる。注記「稼働率が100%に近づくほど、待ち時間は際限なく伸びます」を添える
- 処理タイムライン：早回し中は「経過 23分」のような実時間カウンタを出し、ピークの1時間が終わったところで「このピークは実際には1時間です」と出す
- 小さなオシロスコープ：時刻ごとの注文数と、待ちの列の長さ
- 操作ボタン：ピーク再生（自動で1時間を流す）、分解、早回し／実時間、焼き台の台数、カメラ（全体／厨房／焼き台／入口）
- 部品ラベルは引き出し線つき。重なったら優先度の低いほうを隠し、UI や表示パネルの上には置かない
- 成功と失敗は、厨房の表示板のそばに大きな吹き出しでも出す
- 注記：注文数や焼き時間は原理を示すための模型の値です。厨房の配置は一般的な例をもとにしたイメージです。お客さんの動きは目で見える速さに変えた模式表示です。
- Canvas に描く文字は、document.fonts.load で書体を読み込んでから描く
- スマホ幅（390px）：上に見出しとボタン、下のシートに席数・稼働率・①〜⑥・操作をまとめ、グラフとオシロは「開く」で出す

# もっと知る（出典リンクつきの開閉パネル。事実は下の候補のうち、出典を確認できたものだけを使う）
① 【要確認】待ち行列理論のアーラン C 式と、稼働率が1に近づくと待ち時間が発散する性質（出典の候補：待ち行列理論の教科書、大学の講義資料）
② 【要確認】リトルの法則（列に並ぶ平均人数 ＝ 到着率 × 平均の待ち時間）（出典の候補：J. D. C. Little の1961年の論文、教科書）
③ 【要確認】鰻の蒲焼きは、注文を受けてから焼く店が多く、提供までに時間がかかることが多い（出典の候補：業界団体、専門店の公開情報）
④ 【要確認】客席の回転率と厨房の処理能力の釣り合いが、飲食店の出店計画の基本になる（出典の候補：中小企業庁や日本政策金融公庫の開業の手引き）

# 検証用フックと録画モード
- window.__lab = { ready, setSeats(n), setGrills(n), getState(), tap(), setExploded(on), setCamera(name, instant), setSpeed('fast'|'real') }
  - setSeats の直後の getState は、稼働率・平均の待ち時間・成功・失敗の判定まで反映済みの値を同期で返す
- ?demo=1 で30秒の自動再生にする。__lab.renderDemoFrame(t) で、時刻 t の状態を1フレーム同期で描けるようにする（動画の書き出し用）
- 台本と字幕（画面下中央に大きく、背景の帯つき）：
  - 0〜3秒　店全体の模型「鰻は注文を受けてから焼くので、焼き台が店の心臓です」
  - 3〜7秒　焼き台へ寄る「注文の粒は、焼き台の空きを待って順番に焼かれます」
  - 7〜12秒　席がゆっくり増える「席を増やすと、焼き台の稼働率が上がっていきます」
  - 12〜14秒　しきい値を越える「稼働率が8割を越えたあたりで、待ちの列が急に伸び始めます」
  - 14〜18.5秒　早回しのピーク「待ち時間は少しずつではなく、崖のように増えます」
  - 18.5〜23秒　適正な席数に戻して提供「焼き台に少しの余裕を残すと、待ち時間は短く安定します」
  - 23〜27秒　席を増やしすぎる→行列が店の外へ「席を増やしすぎると、売上より先に待ち時間が増えます」
  - 27〜30秒　分解した引きの絵「だから出店では、席数と焼き台の数を一緒に決めます」

# 進め方
実装したら Playwright でスクリーンショットを撮り、自分で見て直す作業を最低3回繰り返してください。
最初の画面、しきい値の瞬間、成功、失敗、分解、スマホ幅は必ず確認すること。
最後に 1920×1080・30fps で動画を書き出し、成功の瞬間に「チン」、失敗の瞬間に「ブブー」を ffmpeg で重ねてください。
そのうえで、字幕と絵が台本どおりかを確認してください。
