# 記入例：交通系ICカードと自動改札機

実際に使った依頼文。完成品は `ic-card/index.html` と `ic-card/video/ic-card-demo.mp4`。

---

交通系ICカードと自動改札の仕組みを見せる、インタラクティブな3D解説ページをHTML 1枚で作ってください。日本のSNSに30秒の画面録画を投稿して、多くの人に見てもらうのが目的です。

# 見せたいこと
毎日ピッとしているICカードには電池がない。改札が出している見えない磁場から電気を受け取り、ほんの一瞬だけ動いて返事をしている。これを、光る磁場と「カードを近づける」操作1つで体感させる。
最初の2秒で「改札」「ICカード」「光る磁場」が一目で分かる絵にすること。

# 技術の条件
- index.html 1枚。three.js は importmap で https://cdn.jsdelivr.net/npm/three@0.183.2/ から読む
- 外部の3Dモデル・画像は使わない。形はすべてコードで作り、模様は CanvasTexture で描く
- フォントは Google Fonts のみ。それ以外の外部通信はしない
- 60fps、コンソールエラー0。ピクセル比は低めから始め、余裕があれば上げる

# 守ること
- 他人の作品のコードや見た目を参照・模倣しない
- Suica・PASMO・ICOCA のロゴやキャラクター、券面、特定の鉄道会社の改札の形や配色（読み取り部の青く光るリングなど）、非接触決済の4本の弧のマークは使わない。呼び名は「交通系ICカード」「自動改札機」
- 画面の文言はすべて日本語。「！」と絵文字は使わない。「磁場」と「磁界」を混ぜない
- 改札機の内部は「公開情報をもとにしたイメージ」と明記する

# 体験の流れ
① カードが読み取り部の上に浮いていて、読み取り部の上では磁力線のドームが脈打っている
② カードを上下にドラッグして近づける。ホイール、スライダー、↑↓キーでも同じ値が動く。カードに触れたときだけカード操作、それ以外はカメラ回転
③ 近づくほどカードのコイルが琥珀色に光り、電圧メーターがしきい値に向かって急に伸びる
④ しきい値を越えた瞬間にICチップが白く光って起動し、スロー（約40倍）で処理が進む。①ポーリング 改札がカードを探す ②応答 カードが番号を返す ③相互認証 本物どうしか確かめ合う ④読み出し 残高や記録を読む ⑤書き込み 新しい記録を書く ⑥完了 ピッと鳴って通れる
⑤ 完了で短いサイン波の「ピッ」、表示器に「残高 1,850円」。扉は開いたまま
⑥ 途中でカードを離すとチップの電源が落ちて中断。表示器が赤で「もう一度タッチしてください」。カメラが少し引いて扉が通路の中央へ閉じるのを見せ、数秒後に開き直る
⑦ 「分解」ボタンで改札機（上蓋、読み取りユニット＝樹脂カバー／アンテナコイル基板／制御基板、表示器、扉ユニット、通行検知センサー）とカード（表面フィルム／コイルとチップのシート／芯材／裏面フィルム）が浮き上がる。カードは3倍に拡大してそう明記する。アンテナコイル基板には小さな磁場のドームを付けたまま浮かせる

# 物理（原理は正しく、数値は模型の値）
- 単位は 1=1cm。カードは 8.56×5.40×0.076cm
- 読み取りコイルは半径4cmの円ループ。ビオ・サバールの法則を128分割で数値積分するか、楕円積分の厳密式で磁場を出す
- 磁力線はループの内側 ρ=0.35a〜0.9a から RK4 でトレースし、外側で面に戻るところまで追う。12方向に回す。遠くへ飛ぶ電波の絵にはせず、コイルの近くにとどまる閉ループのドームにする
- 明るさは |B| に対して単調（遠いほど暗く細い）。ただし帰りの脚も読める程度に圧縮する
- 交流は、光の粒の流れる向きが半周期ごとに反転し、全体が |cos ωt| で脈打つ形で表す（表示上の周期約1.2秒の模式表示）
- カードのコイル面を7×7点でサンプリングして磁束を出し、V=kΦ とする。読み取り面から約5.5cmでしきい値を越えるように k を合わせ、上限で頭打ちにする
- 改札→カード：磁場の強さを少し弱めたり戻したりして0と1を送る（振幅変調）。「振幅を10%下げる」とは書かない
- カード→改札：カードは電波を出さず、中の負荷を切り替えて磁場をわずかに揺らして返事をする（負荷変調）。光るのはカードのコイルと、読み取りコイルのわずかなちらつきだけにする。カードが電波を放っているように見せない
- ゼロ長ベクトルの normalize や負の数の pow で NaN を出さない（黒い点線のノイズの原因になる）

# 見た目
舞台は終電後の駅の改札口。深い藍色〜黒の空気、濡れたタイル床の映り込み、天井の蛍光灯の帯、遠くにぼけた白い明かり。改札機はつや消しのステンレスと濃いグレーの樹脂。
色の約束：磁場は青白、カードが受け取った電気は琥珀、チップの起動は白い閃光、エラーは赤、読み取りコイルは銅色（発光は弱く）。UIは白〜グレーの細線で、金色の装飾は使わない。
ブルームは解像度を落として控えめに使う。

# 画面
- 見出し「ICカードはなぜ電池なしで動くのか」は最初の3秒だけ上中央に大きく出し、操作が始まったら小さく畳む
- リード：毎日ピッとしているICカードに電池は入っていません。改札が出している見えない磁場から電気を受け取り、ほんの一瞬だけ動いて返事をしています。カードを読み取り部に近づけて、その瞬間を見てください。
- 電圧メーター：線形。しきい値の破線に「チップが動く最低ライン」と付ける
- 距離と電圧の小さな曲線グラフ：現在値の点と約5.5cmの縦線を入れ、注記「コイルから十分離れると、磁場は距離の3乗に反比例して弱まります」を添える
- 処理タイムライン①〜⑥：スロー中は「経過 0.063秒」のような実時間カウンタを出し、完了時に「カードと改札のやりとりは実際には約0.1秒です」と出す
- 小さなオシロスコープ：搬送波と、改札が送るときの包絡線のへこみ、カードが返すときの小さな揺らぎ
- 操作：タッチ（自動で近づけて離す）、分解、スロー／実時間、カメラ（全体／読み取り部／カードの中／改札の中）
- 部品ラベルは引き出し線つき。重なったら優先度の低いほうを隠し、UIや表示器の上には置かない
- 完了と中断は、表示器のそばに大きな吹き出しでも出す
- 注記：距離と電圧は原理を示すための模型の値です。改札機の内部は公開情報をもとにしたイメージです。磁場の往復は目で見える速さに落とした模式表示です。
- 表示器などの Canvas 文字は、document.fonts.load で書体を読み込んでから描く
- スマホ幅（390px）では、上に見出しとボタン、下のシートに距離・電圧・①〜⑥・操作をまとめ、グラフとオシロは「開く」で出す

# もっと知る（出典リンクつきの開閉パネル。事実はこの8つだけを使う）
① カードに電池は入っていません。読み取り機がつくる磁場から電磁誘導で電気を受け取り、同じ13.56MHzから動作のタイミングも作っています。（NTT技術ジャーナル 2008年3月号 https://journal.ntt.co.jp/backnumber2/0803/files/jn200803081.pdf ）
② 磁場の向きは1秒に1356万回往復します（13.56MHz）。（ソニー https://www.sony.co.jp/Products/felica/about/scheme.html ）
③ カードと読み取り機のやりとりは暗号処理を含めて約0.1秒です。（同上）
④ いちばん速く通る人がカードを読み取り範囲に入れている時間は約0.2秒です。改札の処理はこの中に収まるように設計されました。（JRTR No.50 https://www.ejrcf.or.jp/jrtr/jrtr50/6_15.html ）
⑤ 最初の試験（1994年）は2.4GHzの電波を使う電池入りのカードで、電波が人の体の水分に吸われて通信範囲が小さくなりました。2回目（1995年）は周波数を32MHzに下げましたが電池の劣化などの課題が残り、3回目の試験（1997年）で13.56MHz・電池なし・タッチ方式に切り替えました。（JR東日本テクニカルレビュー No.4 https://www.jreast.co.jp/development/tech/pdf_4/24-31.pdf ）
⑥ 「かざす」ではなく「タッチ」と案内されているのは、試験でかざし方がばらつき、通信の時間が足りないことがあったからです。（同上）
⑦ 扉を開けたまま判定する方式は、1960年代に近鉄と立石電機（現オムロン）が開発したもので、当時は外国に例のない仕組みでした。（オムロン https://www.omron.com/jp/ja/news/2007/11/c1127.html ）
⑧ 技術はソニーが開発したFeliCaで、通信速度は212kbpsまたは424kbpsです。2001年11月18日に首都圏424駅でSuicaが始まり、非接触ICカード技術は「戦後日本のイノベーション100選」に選ばれています。（発明協会 https://koueki.jiii.or.jp/innovation100/innovation_detail.php?eid=00098 ）

# 検証用フックと録画モード
- window.__lab = { ready, setDistance(cm), getState(), tap(), setExploded(on), setCamera(name, instant), setSpeed('slow'|'real') }。setDistance の直後の getState は電圧・起動・中断まで反映済みの値を返す
- ?demo=1 で30秒の自動再生。__lab.renderDemoFrame(t) で時刻 t の状態を1フレーム同期で描けるようにする（動画の書き出し用）
- 台本と字幕（画面下中央に大きく、背景の帯つき）
  0〜3秒 全体の絵「毎日ピッとしているICカードに電池は入っていません」
  3〜7秒 読み取り部へ寄る「改札の読み取り部は見えない磁場を出し続けています」
  7〜12秒 カードがゆっくり近づく「カードを近づけると中のコイルに電気が流れ始めます」
  12〜14秒 チップ起動「ある距離を越えた瞬間にチップが目を覚まします」
  14〜18.5秒 スローで通信「カードは電波を出さず、磁場をわずかに揺らして返事をします」
  18.5〜23秒 完了と残高「カードと改札のやりとりは実際には約0.1秒です」
  23〜27秒 もう一度タッチして途中で離す→扉が閉じる「途中で離すと電気が切れて処理が止まり、扉が閉じます」
  27〜30秒 分解した引きの絵「だから鉄道会社は「かざす」ではなく「タッチ」を案内しています」
