# three.js 3D解説ページと SNS 用動画

交通系ICカードと自動改札機の解説（`ic-card/index.html`）を作ったときの手順と、そこで得た教訓をまとめたもの。
題材が変わっても、次の流れはそのまま使える。

1. 単一の HTML でページを作る。
2. 検査用のフックを用意する。
3. デモを決定的に描画できるようにする。
4. Playwright でセルフレビューする。
5. ffmpeg で動画に仕上げる。

## 1. 着手前に仕様を固める

依頼文から次の項目を抜き出し、チェックリストにしてから作業を始める。書かれていない項目は、下に書いた既定値を使う。

- **冒頭2秒で何が読めるか**
  - 主役（装置・物体・目に見えない場）が最初のフレームで全部見えるようにする。
- **物理のモデル**
  - 値は模型値でよいが、原理は正しくする。
  - 解析解があれば解析解を使う。例：ループコイルの磁場は楕円積分（K, E を AGM で計算）で求め、Biot–Savart で検算する。
  - 力線は RK4 で追跡する。
  - NaN を出さないようにガードし、最大値でクランプする。
  - 見た目の明るさは物理量に対して単調にしつつ、`pow(x, 0.4)` 程度で圧縮する。
- **禁止事項**
  - 他人の作品を参照・模倣しない。
  - 実在の企業ロゴ、キャラクター、券面、特定企業の配色は使わない。
  - 呼び名は依頼の指定に従う。
- **文言の規則**
  - 画面の文言はすべて日本語にする。
  - 「！」と絵文字は使わない。
  - 同じ概念の用語を混ぜない（例：「磁場」と「磁界」）。
  - 推測を含む部分には「公開情報をもとにしたイメージ」と明記する。
- **外部通信**
  - CDN の three.js（importmap でバージョンを固定）と Google Fonts だけにする。
  - モデルや画像は使わない。形はすべてコードで作り、模様は CanvasTexture で描く。
- **性能**
  - 60fps で動き、コンソールエラーは0件にする。
  - pixel ratio は低めに始め、描画コストの平均を見て上げ下げする。
- **台本**
  - 秒単位の区間ごとに「字幕・カメラ・状態」の表を作る。
  - この表が、実装と検証の両方の基準になる。

## 2. ページの構成（単一の index.html）

- **物理と表示を分ける**
  - 物理は純粋関数にまとめる（例：`fieldAt`, `fluxThroughCard`, `voltageAt`）。
  - 重い計算は起動時に表にしておき、補間して使う。こうすると `getState()` を同期で返せる。
- **状態機械**
  - 例：`idle → boot → run → done / aborted`。
  - `stepState(dt)` を固定刻みで呼んで状態を進める。描画のフレームレートには依存させない。
  - 実際の処理が0.1秒程度で終わるものは、約40倍のスローで見せる。表示は「スロー表示（約40倍）」「実時間」で切り替え、完了時に実時間を明示する。
- **カメラ**
  - プリセット（全体、注目部、中、分解など）を `{pos, tgt}` の表で持つ。
  - 切り替えは補間して見せる。
- **ラベル**
  - 引き出し線付きにし、優先度の高い順に貪欲法で配置する。
  - 候補位置を6つ試し、次のどちらかにかかるものは捨てる。
    - UI パネルや字幕帯の矩形
    - 表示器など隠してはいけない領域の矩形
- **吹き出し**
  - 完了や中断などを知らせる大きな吹き出しは、左右のパネルとスマホのボトムシートに重ならないよう座標をクランプする。
- **Canvas に描く文字**
  - `document.fonts.load(...)` が終わってから描く。
- **スマホ（幅390px）**
  - タイトルとボタンを上部に置く。
  - 距離、状態、ステップは下部のボトムシートに置く。
  - グラフとオシロは「開く」ボタンで展開する。
- **フック**：`window.__lab` に次を公開する。
  - `ready`
  - `setDistance(v)` と、同期で結果を返す `getState()`
  - `tap()`, `setExploded(on)`, `setCamera(name, instant)`, `setSpeed()`
  - 検査用の `pause(on)` と `advance(sec)`：1/60 刻みで進め、最後に描画する。
  - `renderDemoFrame(t)`

### デモと決定的描画

- `?demo=1` を付けて開くと、台本どおりに自動再生する。
- `renderDemoFrame(t)` は、毎回 t=0 から dt=1/120 で再シミュレーションしてから1回だけ描画する。
  - こうすると、どの時刻を指定しても同じ絵になる。
  - 状態遷移の時刻（boot, done, abort など）を `events` として返し、音と字幕の同期に使う。
- 外部から `renderDemoFrame` を呼んだら `demoExternal = true` にし、内部の自動再生ループを止める。
- **CSS の transition は壁時計で動く**ので、書き出しのときは決定的にならない。
  - 書き出し時は body に `frozen` クラスを付け、`transition: none !important` にする。
  - タイトルの縮小やパネルのフェードインは、`t` から計算した不透明度で手動でクロスフェードする。
- 台本の区間の境目で状態が切り替わるように、距離の変化 `demoDistance(t)` を調整する。
  - 閾値を越える時刻（例：12.18秒）を `events` で確認しながら合わせる。

## 3. 見た目の既定値と、実際に踏んだ落とし穴

- **白飛び**
  - UnrealBloom は半分の解像度で使い、threshold は0.9程度にする。
  - 場の線は加算合成の細いチューブで描き、halo と点光源を控えめにする。
  - 環境マップ（PMREM）の強さを上げすぎない。
  - 金属の縁が光りすぎたら envMapIntensity を下げる。
- **カードの印刷が逆さま**
  - 上向きの面に貼った CanvasTexture は `texture.flipY = false` にしないと、手前から見て上下が反転する。
  - 180°回転で直すと、今度は左右が鏡像になる。
- **`position: fixed` の要素の `offsetParent` は常に `null`**
  - 可視判定に使うと、パネルや字幕がすべて衝突判定から漏れ、ラベルが字幕の下に潜る。
  - 可視判定は `getComputedStyle` の display、visibility、opacity で行う。
- **ブラシ加工したステンレスが木目に見える**
  - ノイズのコントラストを下げ、repeat を細かくする。
- **字幕の途中改行**
  - `left:0; right:0; margin:auto; width:fit-content; max-width:90vw` で中央に置く。
- **スマホで主役がボトムシートに隠れる**
  - `camera.setViewOffset(w, h, 0, h*0.2, w, h)` で描画範囲を上にずらす。
  - 縦長の画面では fov を少し広げる（例：38 → 50）。
  - ボトムシートは `max-height` と `overflow: auto` で伸びすぎないようにする。
- **暗い部品が見えない**（中断時に閉じる扉など）
  - 明度を上げ、状態に応じて縁を赤い emissive で光らせる。
  - 中断時の専用カメラで、その部品を画面の中心に捉える。
- **見た目の方針**
  - 情報の UI は白と灰の細線で統一し、金色は使わない。
  - 色に意味を持たせる。例：場は青白、給電は琥珀、起動は白、エラーは赤。

## 4. 検証の手順（最低3周、毎回画像を見て直す）

`scripts/` にある道具を使う。作業ディレクトリ（scratchpad など）で準備する。

```sh
npm i three@<ページと同じ版> playwright-core @ffmpeg-installer/ffmpeg sharp
cp <このスキル>/scripts/* .
(cd <ページのディレクトリ> && python3 -m http.server 8765 &)
```

- `lab.cjs` は、jsDelivr の three.js をローカルの `node_modules` から返す。
- Google Fonts は curl 経由でキャッシュして返す。サンドボックスのプロキシ越しだと、Chromium の直接取得は失敗しやすいため。
- `page.goto` は `waitUntil: 'domcontentloaded'` で行い、`__lab.ready` を待つ。
- ソフトウェア描画は遅い。壁時計で待たず、`pause(true)` と `advance(sec)` で状態を進めてから撮る。

各周で、次のすべてを撮って確認する。

1. 最初の画面：主役、磁場、ラベルが2秒以内に読めるか。
2. 閾値を越えた瞬間：チップが光るなどの演出。
3. 通信の途中：ステップ表示と経過時間のカウンター。
4. 完了：吹き出し、表示器、実時間の注記。
5. 中断：赤い表示、扉が閉じる、カメラが引く。
6. 分解表示と、内部を見せるカメラ。
7. スマホ幅390×844：上部のボタン、ボトムシート、「開く」、「もっと知る」パネル。
8. デモの各区間の代表時刻：`node frames.cjs out/d 1,5,10,12.4,16,20,24,26.5,28.5`
   - 出力される `events` の時刻が台本の区間に入っているかを確かめる。

撮った画像は `node grid.cjs sheet.png ...` で一覧にしてから見る。
さらに次を確認する。

- コンソールエラーが0件であること（`logs`）。
- 文言の検査：
  - `grep -c 磁界 index.html` のような禁止語の検索
  - 「！」の検索
  - 絵文字の範囲の走査
- 外部 URL の列挙：リンクの `href` 以外で、通信先が CDN と Google Fonts だけであること。

## 5. 動画の書き出しと効果音

```sh
node export.cjs video-noaudio.mp4 30 30   # 900フレームを JPEG で ffmpeg に流し込み、H.264 CRF16 で出力（ソフトウェア描画で1フレーム約1.7秒）
python3 cues.py beeps.wav 30 '2400,18.175,0.13,0.45' '3000,26.017,0.07,0.35,5,0.12'   # 時刻は export の EVENTS から取る
ffmpeg -i video-noaudio.mp4 -i beeps.wav -c:v copy -c:a aac -b:a 192k -shortest final.mp4
```

- 書き出しは時間がかかる。`run_in_background` で実行し、終わるのを待つ。
- 効果音の時刻は、必ず `events` の実測値から取る。台本の秒数を使わない。
- `@ffmpeg-installer` の ffmpeg は2018年版で、`anullsrc` の `d` オプションや `amix` の `normalize` オプションがない。音は `cues.py`（標準ライブラリだけで書いたもの）で作る。
- 完成後に確認すること。
  - `ffmpeg -i final.mp4` で長さ、解像度、fps、音声トラックを見る。
  - 効果音の時刻とそれ以外で `-af volumedetect` を比べ、音が鳴っている区間を確かめる。
  - 代表時刻のフレームを `-ss t -frames:v 1` で抜き出して一覧にし、字幕と絵を台本の表と照合する。

## 6. 仕上げ

- 解説ページは既存のコードとは別のディレクトリに置く。例：`ic-card/`。
- 開き方とフックの一覧を書いた短い README を添える。
- 動画と確認用の一覧画像もコミットし、指定されたブランチにプッシュする。
- ユーザーには動画と確認用の一覧画像を送る。報告では次を簡潔に伝える。
  - 台本との照合表
  - イベントの時刻
  - コンソールエラーの件数
