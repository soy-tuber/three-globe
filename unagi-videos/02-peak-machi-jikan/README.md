## 模型の中身（値はすべて原理を示すための模型の値）

- 待ち行列：焼き台 c 台を窓口とする M/M/c。注文数 λ ＝ 0.5件／席・時 × 席数（席の回転は一定）、1台が1時間に焼ける数 μ ＝ 60／11（平均の焼き時間 11分）、稼働率 ρ ＝ λ／(cμ)。
- 平均の待ち時間：アーラン C 式 Wq ＝ C(c, λ/μ)／(cμ − λ)。平均の待ちの件数は Lq ＝ λWq（リトルの公式）。ρ ≥ 1 では平衡状態がないので「列が伸び続ける状態」とし、表示は90分で頭打ちにします。
- 焼き台4台では、33席で稼働率76%・待ち時間6分、38席で稼働率が85%の目安を越え（87%・16分）、40席で27分、41席で94%・40分、44席以上で100%を越えます。
- 判定：稼働率85%未満は「適正」、85%以上は「混雑」、待ち時間30分以上（待ちの限界、模型の値）か稼働率100%以上は「限界を越えた」。
- 粒の動き：乱数の種を固定した離散事象シミュレーション（先着順、空いた焼き台から使う）。席数と焼き台の組ごとに、十分に助走した12時間分の平衡状態の区間を作り、その時間平均の列の長さがリトルの公式の Lq と25%以内で合うものを使います。席数を変えると、新しい組の区間に切り替わります（実際の店では、たまった列が解消するまでに時間がかかります）。混雑した組に切り替えたときは、列の長さがその平均くらいの時点から再生します。稼働率が96%以上の組は、画面の列の長さから始めてそのまま進めます。
- 画面に出す平均の待ち時間と稼働率は式の値で、粒はそれを目で見せる補助です。お客さんと注文の粒の移動は、目で見える速さ（1.3秒、0.9秒など）に変えた模式表示です。入口の外まで伸びる列は、待ちの件数を店の外へ続く一本の列として示した模式表示です。
- デモの4つの組（30席、33席、39席、41席）は、見やすい区間から再生するように開始位置を決めています（統計の性質は変えていません）。

## フック

| 名前 | 内容 |
| --- | --- |
| `ready` | 準備ができたかどうか |
| `setSeats(n)` | 席数（12〜64）を設定し、状態を同期で返す（稼働率・平均の待ち時間・成功・失敗の判定まで反映済み） |
| `setGrills(n)` | 焼き台の台数（2〜6）を設定し、状態を同期で返す |
| `getState()` | 現在の状態を返す（同期）。`waitMinutes` は稼働率100%以上で `null`、`verdict` は `ok` / `busy` / `fail` |
| `tap()` | ピーク再生（今の席数と台数で、ピークの1時間を早回しで流す） |
| `setExploded(on)` | 分解表示の切り替え |
| `setCamera(name, instant)` | カメラの切り替え（`overview` / `kitchen` / `grill` / `entrance`） |
| `setSpeed('fast'｜'real')` | 早回し表示（約540倍）と実時間の切り替え |
| `renderDemoFrame(t)` | デモの時刻 `t` 秒のフレームを同期的に、決定的に描画する |
| `pause(on)`, `advance(sec)` | 検査用：自動の描画を止め、1/60秒刻みで進めてから1回描画する |
| `waitMinutes(seats, grills)`, `lookFrom(pos, tgt)`, `perf()` | 検査用：式の平均の待ち時間（分）、任意の視点、描画コストと画素比 |

## 依頼文から変えたところ

- ピークの1時間は、30秒の動画の14〜18.5秒の区間に収めるため、「約60倍」ではなく「早回し表示（約540倍）」にしました（1秒で店の9分）。しきい値を越えた瞬間（12.2秒）にピークが始まり、18.9秒に1時間が終わって「このピークは実際には1時間です」を出します。
- 成功の「チン」は、ピークの1時間が終わった時点で席数が適正（稼働率85%未満、待ち時間30分未満）のときに鳴らします。失敗の「ブブー」は、待ち時間が限界の30分を越えた瞬間に鳴らします。失敗の数秒後に、席数は待ち時間が6分以内になる数（焼き台4台なら33席）に自動で戻ります（デモでは台本どおりに戻します）。
- グラフには、失敗の判定に使う「待ちの限界（模型の値）」30分の線を足しました。
- 注文の流れ①〜⑥は、白い輪の付いた1つの注文がいまどの段階にいるかを示します。
